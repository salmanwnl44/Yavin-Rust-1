# Yavin extension system — final security and release-readiness audit (EXT-23)

**Date:** 2026-10-19. **Scope:** EXT-01 … EXT-22, audited against the code, tests and packaged application at commit `8bd7173` (EXT-21/22) plus the EXT-23 regression tests. **Method:** every security-critical requirement traced to its enforcement point and its tests; the suites re-run; every earlier mutation proof re-run against today's code (drifted ones re-targeted); the deployed registry verified over the network; installer behaviour measured with five real MSI packages. Earlier module reports were not accepted as evidence.

Evidence kinds: **native** (Rust tests through the real service, installer and host), **packaged** (the release MSI driven end to end), **mutation** (the protection removed, a test must fail), **live** (network: the deployed GitHub registry, open-vsx.org), **installer** (real `msiexec` installs), **UI** (mock window tests: messaging only — never a boundary).

## Installer experiment (row 12)

Five MSI packages built from this commit with the disposable test identifier `com.yavin.ide.e2e` (never launched; no profile or extension data created; everything uninstalled afterwards — nothing left registered or on disk). Each package's ProductCode, version and `Upgrade` table were read from the MSI itself.

| Package | Version | `MajorUpgrade`                                                                              |
| ------- | ------- | ------------------------------------------------------------------------------------------- |
| A, B    | 2.0.0   | this build (`allowDowngrades: false`): `AllowSameVersionUpgrades="yes"`, downgrades refused |
| C       | 1.9.0   | this build                                                                                  |
| D       | 2.0.1   | this build                                                                                  |
| E       | 1.9.0   | as every build before EXT-21: `AllowDowngrades="yes"`                                       |

| Installed | Then installed          | Result                                                                             |
| --------- | ----------------------- | ---------------------------------------------------------------------------------- |
| —         | A 2.0.0                 | installed                                                                          |
| A 2.0.0   | B 2.0.0 (another build) | **A silently replaced** (`WIX_UPGRADE_DETECTED`, `RemoveExistingProducts`; exit 0) |
| B 2.0.0   | D 2.0.1                 | upgraded                                                                           |
| D 2.0.1   | A 2.0.0                 | **refused**: "A newer version of Yavin IDE is already installed." (exit 1603)      |
| D 2.0.1   | C 1.9.0                 | **refused** (exit 1603)                                                            |
| D 2.0.1   | E 1.9.0 (old-style)     | **silently downgraded** (exit 0)                                                   |

**Findings.** (1) The downgrade check is the _incoming_ package's: `allowDowngrades: false` protects only against packages built with it. Every Yavin build before EXT-21 allows downgrades, so any of them installs over any newer Yavin. (2) Every build so far is version `2.0.0`, and same-version installs are treated as upgrades: today any old build replaces the current one without a warning. (3) With a strictly increasing version and only new-style packages published, downgrades are refused. **No Yavin installer has ever been published** (GitHub: 0 releases, 0 tags), so no old-style package is in users' hands.
